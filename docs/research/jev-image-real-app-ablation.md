# Jev 真实 TextEdit 文本与图片对照

## 结论

本轮在安装的TextEdit 1.20（415）、macOS 26.6.2中创建实验专用临时RTF，
要求将红色North或South行替换为DONE，保留其他文字。界面是真实应用，文档内容
由实验生成；不是用户个人文档，也不是手工仿制的应用页面。Jev为1.14.0。

完整分母每臂4任务：图片3次实际模型选择均正确，其中2次实际替换完成、1次被
stale_reference拦下；另1次在调用前因画面不稳定拒绝。文本3次实际调用均弃权，
另1次调用前拒绝，实际完成0/4。图片完成2/4，不能把模型选择3/3写成闭环3/3。
只有scene-01-p1和scene-02-p1两组双方都实际调用：图片正确2/2、文本弃权2/2，
其中图片真正完成1/2。配对子集按“双方有调用”选择，不按答案或成功筛选。

这给出了当前纯文本AX观察包中图片的增量证据：文字中没有逐行颜色，图片能帮助
在两个合法候选中选对。它不证明Jev优于其他视觉模型，也不代表AX平台不能提供
富文本属性；本轮没有Qwen或其他模型对照。仅两个颜色分配、两个位置、同一任务族，
不作显著性或跨应用可靠性推断，生产默认不变。

## 对照与执行边界

TextEdit真实工具栏具有bold/italic/underline/alignment标签，未人为删除。完整AX
描述观察因正文AXDescription返回-25200标记不完整；两臂均提供该真实观察，原生
执行仍用已有、完整的TextEdit标识符路径，不放宽全局AX错误或原派发约束。
当前观察包有正文、工具栏和颜色控件，但不抽取正文逐字颜色。固定选中黑色标题，
使工具栏颜色不会因目标行选区而泄露红蓝分配，同时减少光标动画。

两种红蓝分配×两个位置×文本/图片，臂顺序交替，位置变化时两个候选顺序反转。
每项最多1次模型选择、1次原生fill；两个完整替换文本均预先给定，模型不生成
新参数。私有完成正文只用于Controller和独立读回，公开模型投影删去completion；
两臂都有同种当前AX/候选/意图/几何，只有图片臂发送PNG。临时文件名、进程引用
和任务ID随新会话变化，不能宣称原始请求逐字相同。

两臂都捕获画面并遵守相同稳定帧门，故本轮比较图像信息增量，不能用含截图准备的
文本臂耗时代表优化后的纯文本生产延迟。图片为绑定窗口，不含其他应用；实际主
任务源帧为1373×1920，上传的准备图为1121×1568（预处理长边上限1568）。候选
映射到准备图像素，Box使用相对准备图的0–1归一化坐标，不能将图内像素直接当
屏幕坐标。保留原窗口/显示器几何及源图、准备图哈希。
