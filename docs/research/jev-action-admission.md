# 动作级文字准入：可区分目标不受无关重复候选阻塞

承接[计划](../plans/active/jev-action-admission.md)及[96项路由分析](jev-calibration-route-analysis.md)。
本片只验证规则/宿主链路，不运行新的Jev或视觉模型，不作质量/耗时/采用结论。
原模型成功率仍是旧研究的结果；本轮不把旧视觉选择当成Jev的新答案。

## 实现与边界

新增benchmark专用ActionAdmissionSelector，直接注入原ComputerUseController；不注册
生产factory模式、配置或默认开关。原候选组、观察、动作参数及binding完整保留，
不给模型一份删去重复选项的短名单，也不把两个同名目标合并成可执行的一个目标。

原型沿用原歧义身份：role、label、ancestors、current_value、input_key、归一化effect
及changes；checkbox的节点回读key仍不能冒充语义区别。标记重复、空标签及泛名目标，
有至少一个可区分动作时允许一次Jev文字提议；只接受选中的可区分目标。合法弃权
或选中被标记目标时复用原视觉分支；全部被标记则直接视觉。重复状态仍走原有
有限视觉恢复，硬错误/撤权/未知用量向上传播，不改成模型重试。

唯一性只是机械规则。模型仍可能选择一个唯一却不符合目标的动作；允许文字提议
也不代表它会作出正确选择。任务授权、引用/帧校验、动作派发、效果及终态核验仍由
原TaskRuntime/Controller/通道承担。本片没有证明扩大准入后的模型安全或速度。

为了保持旧冻结证据与运行源码不变，本原型在benchmark内隔离谓词，并用全体旧状态
核对它与原全局判定的一致性。复用的物理视觉调用purpose保持computer_use.visual；
逻辑接管另以computer_use_action_admission的accepted=false、next_route=visual_fallback
及原candidate_set_id记录，不得仅看物理purpose把它计作未尝试文字的直接视觉。
原始Jev proposal是提议，接受与否以动作级事件及实际派发区分。

现有真实V/JT执行器、审计/评分和资格入口未接入这个新策略；以后小批实测须冻结
原型源码和新事件口径，不能把它塞入旧冻结目录续跑。当前benchmark无真实调用CLI。

## 既有状态上的规则覆盖

输入来自已归档96项（24 seed、48配对条件），模型选择对应的336个路由步骤、5576个动作候选逐项保留。
调用前因观察不可用、不完整或超限而拒绝/重观察的状态不在此分母；这些前置门未改变。
两臂和两启动条件保持原来的相关性，不把336个步骤当独立任务样本。全局判定复现
116个文字可用与220个需视觉；原型中每个状态均至少有一个可区分候选，因而只是
“允许尝试文字”的状态变多，并不表示所有目标或任务均能由文字完成。

主要看JT的168个步骤：

- 原58步文字可用，110步由整组守卫直接走视觉；原型允许这110步先尝试文字。
  2788个候选中2520个通过机械文字检查，268个仍被阻挡；不删除任何候选。
- 110个旧视觉步骤中，106个旧选择通过新文字守卫，4个是非动作回复。它们是
  已观察视觉答案的兼容性回放，不是106次新的Jev正确选择或可节省的图片调用。
- SQLite编辑页62步的旧视觉选择全部通过新机械守卫；SQLite整产品86个原需视觉
  步骤中84个旧选择通过。linkding相应24步中22个通过。
- 正例JT156步中，100步原需视觉，100个旧视觉选择均通过新守卫；负例JT12步
  中10步原需视觉，6个旧选择通过、4个非动作回复。负例仍有唯一无关候选，
  不能因为候选可区分就断言无误操作风险。

额外文字调用可能增加最终仍需视觉的步骤耗时；旧数据没有这些新增Jev答案和耗时，
因此不估新方案准确率、完成率、节图量、延迟、费用或采用收益。
