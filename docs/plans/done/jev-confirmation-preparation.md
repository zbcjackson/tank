1. 冻结准备协议：24个校准任务（每产品6正常、4已知GET故障恢复、2负例），
   公共目标/输入与私有验收分离，种子/任务身份与旧开发任务不重合。校准集可
   检验可行性/估计方差，但不得计入随后确认。确认集使用独立命名空间与新种子，
   模型测量前不用于调提示/路由；未冻结正式N之前不生成可收费执行许可。
2. 样本量分析：完整保留主计划质量/安全/非劣/速度门，主要改善终点选速度；
   展示独立单位、配对/聚类、置信区间、功效假设与敏感性。少量全成功不能估计
   稀有失误/恢复分布，零失误所需N只是可通过门的最低数，不冒称80%功效。
   明确下一阶段数值N须先有新校准的方差/失配率，再冻结正式确认。
3. 在新目录冻结24任务、资格驱动及现有执行源/原产品hash；按预声明顺序运行
   无模型脚本。正常/恢复要求正确编辑、仅目标值变化、单POST和真实返回列表；
   负例要求业务不变，并验证缺目标或撤权状态，不把脚本自行停止当系统决策。
   保存全部成功/失败、物理DB、HTTP、观察/capture/原始PNG及清理。不得为模型
   可选性修改原产品页面；任务不合格则如实标记，不能悄悄替换/剔除。
4. 输出研究报告、协议/任务/样本量工件与交互面板，逐成员核验/实际凭据扫描/
   旧档hash核验；下一执行配方必须匹配本协议及新源freeze，不能直接执行旧配方。
5. 全部适用验证后，按agents/code-reviewer.md做review-and-refactor，最多三轮；

   不因准备结束声称正式样本量或收费执行器已准入。
