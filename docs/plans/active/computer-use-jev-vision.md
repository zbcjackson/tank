# Computer Use：Jev适用路由与视觉兜底

## 目标与本轮范围

用户目标是操作稳定性、完成质量和速度改善：适用时使用Jev，结构化证据不足或
Jev不能可靠处理时使用视觉方案，并保留统一的授权、预算、回执、独立核验和清理。
费用是完整任务的约束/次要指标，不以省费自动替代上述目标。

本轮审查已有A/H/J评估及当前实现，识别已证实问题、可检验假设和有效证据边界，
形成研究报告、交互审查面板及新的验证设计。既有冻结、原始请求、结果、阈值、费用
和unknown预留不改；旧研究结案不作为目标混合方案的否定证据。具体代码/新试验
属于后续切片，本轮不自动部署或追加真实调用。

## 步骤

1. 追踪默认A、当前H/J、selector/Advisor与TaskRuntime的数据和调用路径，核对
   是否真正存在视觉兜底，以及切换是否保留原任务状态。
2. 只读复核代表性原始结果、冻结参数、事件与捕获记录：场景覆盖、样本单位、
   失败原因、请求/用量/耗时口径、配对和停止门槛；对派生统计标明范围和限制。
3. 给出面向用户目标的混合设计与最小对照：结构化适用性门、视觉接管/返回、
   规划与选择职责、硬停止、独立效果核验、全部模型与恢复成本。
4. 在独立新样本上设计离线/受控场景，区分机制隔离与端到端研究、正例完成与
   负例安全退出、冷启动与稳态、实际失败耗时与完成效率。数值采用门槛和样本量
   在确认阶段前冻结，不在旧数据上重新挑成功。
5. 本轮研究/计划/现行结论完成后，经验证和独立评审交付；后续按审查结论选择
   一个最小实现/离线验证切片，再单独冻结真实比较，保持生产默认不变。

## Tests

本轮不改变执行行为，不新增镜像单元测试。对原始工件只读，派生分析复核分母、
配对、事件/调用关联、数据缺失和样本相关性；不把缺失字段当作零，不把SDK调用
冒称HTTP线级发送。文档执行一致性与差异检查，面板仅含去载荷的汇总与来源。

后续实现须按TDD扩展既有core/plugin测试与chat.feature，验证：结构可用时Jev
参与、结构不足时真实图片进入视觉模型、视觉后可返回结构化路径、同一任务账本/
授权/期限/回执连续、未知效果只读协调、硬停止不触发兜底派发、各路由独立核验，
以及不泄露评分真值和不把置信度当作正确性证明。

指标测试需包含失败intake仍有一次attempt、fallback start/result只算一次，A/H/J
不同捕获位置能对账；无字段为缺失，不能填零。路径约束需从独立动作轨迹评分，
不能仅靠终态表达式推断未触碰禁用操作。旧strict与旧统计不追溯重判。
