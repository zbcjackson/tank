# M3 冻结 holdout：三配置 × 64 布局 × 两次

2026-09-21。384 次请求和独立原始响应/mask 回放全部完成。Max bbox 与 GPT
point 正例均 **96/96 命中**，但三组同名歧义样本均 **0/16 正确拒绝**。
**三组都不通过完整静态门槛，生产默认不切换。** 这是模型与 adapter 组合的
静态成绩，不是完整任务、原生 computer 接口或 M4 拆分收益验收。

## 冻结、执行和评分

沿用 [冻结记录](../20260921-m3-holdout-freeze/README.md)，三组为 Qwen3.7
point/off、Qwen3.8 Max bbox/off、GPT-5.5 point/none。旧 found 整数 schema，
strict=false、detail=auto、8000 输出上限；其余模型/端点/参数均未改变。
128 请求/配置：48 个正例布局 × 2，加缺失与歧义各 8 布局 × 2。
独立样本是 64 布局，不是 384 个；重复轮按布局聚类，配对区间保留两次重复。

[执行器](../../../../scripts/run_grounding_holdout.py) 经生产 adapter → LLM →
实际 SDK 发送，每次验证冻结 body、图片字节/尺寸/hash。384 次各一次 HTTP，
全部 200，usage 全部已知，无自动重试、接口失败、超时或截断。执行进程
禁止打开 truth；完成后才读取评分真值，并验证其与冻结前 `9cd07e1` 版本一致。
所有原始响应重放生产解析器，SDK 对象、点/框、合法率和 mask 评分逐条核对。

评分沿用冻结口径：点按 floor(value+0.5) 取最近像素，命中必须落在实际可见
mask 内，遮挡与外部区域不算；中心误差单列。格式非法、无输出均计失败。
负例仅在合法解析且没有执行点时算拒绝，数组/越界被拒不能冒充正确拒绝。
旧 found=false 不区分 missing/ambiguous，按真值分层报告拒绝，不报精确状态分类。

## 结果

- **Qwen3.7 Flash point**：合法 112/128；正例命中 **57/96（59.38%）**。
  正例 14 次无合法点；其余合法点中心误差 p95 **469.68 px**，最大 **523.28 px**，
  25 次 >50 px。缺失正确拒绝 16/16；歧义拒绝 0/16，其中 14 次可执行误报、
  2 次格式失败。完整成功 73/128。16 次格式失败全为坐标越界。
- **Qwen3.8 Max bbox**：合法 124/128；正例 **96/96（100%）**，中心误差 p95
  **2.29 px**，最大 **2.63 px**，无 >50 px。缺失拒绝 16/16；歧义拒绝 0/16，
  其中 12 次可执行误报、4 次数组坐标被解析器拒绝。完整成功 112/128。
  实际响应型号 qwen3.8-max-0902，保留请求 snapshot 名称，不隐去别名差异。
- **GPT-5.5 point**：合法 128/128；正例 **96/96（100%）**，中心误差 p95
  **1.82 px**，最大 **2.82 px**，无 >50 px。缺失拒绝 16/16；歧义拒绝 0/16，
  16 次均可执行误报。完整成功 112/128。实际响应 openai/gpt-5.5，provider=OpenAI。

Max/GPT 相对静态 Qwen3.7 基线，正例命中差均为 **+40.63 个百分点**；按 48 个
独立正例布局聚类 bootstrap 95% 区间 **[+28.13, +54.17] 个百分点**。全部
64 布局的成功差为 +30.47 个百分点，区间 [+20.31, +41.41]；负例成功差为零。
这是当前合成分布的描述区间，没有多重比较校正，也不证明真实应用的普遍收益。

三者都在 16 个缺失请求中拒绝，在 16 个同名请求中失败。查看实际冻结提示：
旧协议只要求目标缺失或“不确定”时 found=false，**没有明确要求多个同名目标
时必须拒绝**，而评分要求这种拒绝。保留门槛和失败记录，同时明确归因限制：
结果证明这套模型/提示/协议组合未满足要求，不能单独归为模型识别能力问题。
事后视觉复核 layout-50 确有两个“8”；未修改样本或补偿分数。此前显式 status
实验换过提示且不是同图旧 schema A/B，不能拿来宣称 schema 修复已获验证。

## 结论与后续边界

正例空间定位上，Max/GPT 是有证据的候选；同名歧义处理仍未达标，因此本轮
不采用、不切默认、不把任务成功或独立定位架构写成已验收。原生协议未测，
真实闭环、取消/清理及跨应用仍待后续阶段。

这套 holdout 已被评估，**不能再用于调参并继续称为独立 holdout**。下一步先
在开发样本中隔离“明确要求唯一匹配/多匹配拒绝”的提示与 schema 因素；若
修复后需要重新验收，必须另记新样本/请求预算和新冻结批次，不覆盖本报告。
M4 的 locate 编排仍须实现帧、共享预算、取消和动作反馈；静态 100% 正例命中
不放宽这些条件。
